# Step 2-7 — 本番マイグレーション適用・本番デプロイ

**フェーズ:** Phase 2 — クイズ・検定機能 / Deploy
**依存:** Step 2-6（テスト完了）、Phase 1 [dev-plan-13-deploy-phase1.md](../01/dev-plan-13-deploy-phase1.md)（本番稼働中の VPS・Traefik/Cloudflare 基盤）

---

## ゴール

Phase 1 で本番稼働済みの `line.omise.app` / `api-line.omise.app` に対し、クイズ・検定機能の
DB マイグレーション（Step 2-1 で作成）を安全に適用し、バックエンド・フロントエンドを本番デプロイする。

> 本番 DB は既に Phase 1 の稼働データ（ユーザー・コンテンツ・進捗）を保持しているため、
> **新規テーブル追加のみ**（既存テーブルへの破壊的変更なし）であることを前提に手順を組む。

---

## タスク

### 2-7.1 事前準備

- [ ] 本番 DB のバックアップを取得（`pg_dump`、Phase 1 の日次バックアップとは別に手動スナップショットを残す）
- [ ] Step 2-1 の `007_quiz.up.sql` / `.down.sql` を本番相当のステージング環境（あれば）で事前適用検証
- [ ] マイグレーション適用が既存の Phase 1 API・フロントエンドの動作に影響しないことを確認（新規テーブルのみ追加のため無停止で適用可能なはず、という前提を検証）

### 2-7.2 本番マイグレーション適用

- [ ] `sys/01_infra/deploy.sh`（Phase 1 Step 13 で作成済み）の `migrate` ステップで
      `007_quiz.up.sql` が適用されることを確認
- [ ] マイグレーション適用ログを確認し、エラーなく完了したことを確認
- [ ] 適用直後に `quizzes` / `quiz_questions` / `quiz_choices` / `user_quiz_attempts` / `user_quiz_answers`
      が本番 DB に作成されていることを確認

### 2-7.3 バックエンド・フロントエンドの本番デプロイ

- [ ] Step 2-2〜2-5 の変更を含むイメージをビルド・デプロイ（`git pull` → build → migrate → `up -d` の既存フロー）
- [ ] Admin 用の初期クイズ／検定データを本番で投入（例:「LINE運用クイズ」「基礎LINE検定」）

### 2-7.4 動作確認チェックリスト

- [ ] Admin が本番でクイズ／検定・設問・選択肢を作成できる
- [ ] 未ログインで練習モードのクイズに解答し、正誤・解説が表示される
- [ ] ログインユーザーが検定モードの試験を提出し、最終スコア（・合否）が表示される
- [ ] マイページで練習モードの解答履歴・検定モードの受験履歴/進捗が本番で確認できる
- [ ] 既存の Phase 1 機能（LP・`/learn/`・`/usecase/`・ログイン・レッスン試験・進捗）がデグレしていない

### 2-7.5 ロールバック手順

- [ ] `007_quiz.down.sql` によるロールバック手順を文書化（新規テーブルの `DROP` のみのため、
      既存データへの影響なしにロールバック可能なことを確認）
- [ ] バックエンド・フロントエンドを直前のイメージ/タグに戻す手順を文書化

## 成果物

- 本番マイグレーション適用ログ・確認記録
- ロールバック手順書（クイズ機能追加分）

## 完了条件

- 本番 DB にクイズ・検定関連テーブルが作成され、既存データ・既存機能に影響がない
- 本番で Admin によるクイズ／検定作成、Reader による練習/検定受験・履歴/進捗確認が動作する
- ロールバック手順が検証済みで、必要時に安全に切り戻せる
