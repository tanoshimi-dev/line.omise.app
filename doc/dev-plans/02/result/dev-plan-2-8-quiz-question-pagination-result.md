# Step — 検定モードも1問ずつ表示 + 両モード共通の前へ／次へナビゲーション — 実施結果

計画: [dev-plan-quiz-question-pagination.md](dev-plan-quiz-question-pagination.md)

---

## 実施内容

計画どおりに実施。バックエンド（API・DB）は変更なし — 変わったのはフロントエンドのコンポーネントのみ。

### `ExamRunner.tsx`（検定モード）

- 全設問を1ページに並べていたのをやめ、`index` state で1問ずつページ送りする方式に変更（レイアウトは
  `QuizQuestionCard` と同じ「N / M問」進捗表示 + 設問 + 選択肢）。
- 選択済みの回答は引き続き `answers: Record<string, string[]>` にため込み、API へはまだ送らない。
- ナビゲーション: 最初の設問以外で「前の問題へ」を表示、最後の設問以外で「次の問題へ」を表示、最後の
  設問でのみ「提出する」ボタンを表示。回答の有無に関わらず次へ進める（未回答のまま提出できる既存仕様を
  そのまま維持 — 未回答警告ダイアログの挙動も変更なし）。
- 設問が0件のクイズに対するガード（`このクイズにはまだ設問がありません。`）を追加（`QuizQuestionCard` と
  同じパターン。以前は空配列を `.map` するだけで実害はなかったが、`questions[index]` への直接アクセスに
  変えたため必要になった）。

### `QuizQuestionCard.tsx`（単発モード）

- 各設問の選択状態・採点結果を `QuestionStep` 内部の state からリフトアップし、親コンポーネントの
  `selectedByQuestion`/`resultByQuestion`（設問IDをキーにした Record）に変更。
- 「前の問題へ」ボタンを追加（最初の設問では非表示）。採点済みの設問に戻ると、選択した回答と正誤・解説を
  そのまま再表示し、`POST /api/quiz-questions/:id/answer` を再送しない。
- 「次の問題へ」ボタンは、現在の設問が採点済みの場合のみ表示（未回答のまま次へ進めない既存仕様は維持）。
  最後の設問ではボタンラベルを「結果を見る」に変更し、押すと `finished` 画面（正解数のサマリー）へ遷移。

### テスト

- Vitest:
  - `ExamRunner.test.tsx`: 既存2ケースを「前へ進んでから提出する」操作列に更新。前の設問に戻って回答を
    変更してから提出できることを検証する新規ケースを追加。
  - `QuizQuestionCard.test.tsx`: 既存2ケースの「次の問題へ」を、1問構成のクイズでは最後の設問になるため
    「結果を見る」に修正。2問構成のクイズで「前の問題へ」に戻ると採点結果が再表示され、API が再送され
    ないことを検証する新規ケースを追加。
  - 合計 7 ファイル 30 件、全て pass。
- Playwright (`sys/04_e2e/tests/quiz.spec.ts`): 既存のシナリオはすべて1問構成のクイズ（`seedQuiz` ヘルパー
  が1問しか作らない）を使っており、1問しかない場合は最初の設問がそのまま最後の設問になるため、ページ送り
  UI に変わっても「モード選択 → 解答 / 検定モードは直接『提出する』」という既存の操作列のままで
  変更不要だった。実際に `docker compose build/up -d line-web` でイメージを再ビルド・再起動したうえで
  21件全て pass することを確認済み（バックエンドは今回のタスクでは無変更のため line-api の再ビルドは
  不要）。

## 検証

- `npm run build`（`sys/03_frontend/web`）— 型チェック含め成功。
- `npm run test`（Vitest）— 7ファイル30件 全てpass。
- `docker compose build line-web` → `docker compose up -d line-web` でイメージを反映。
- `npx playwright test`（`sys/04_e2e`, 実際に稼働中のスタックに対して実行）— 21件全てpass。

## 計画からの逸脱

- 計画では「Playwright のシナリオ更新」をタスクに挙げていたが、既存シナリオが1問構成のクイズしか
  使っておらず実質的に変更不要だったため、テストコード自体は変更していない（動作確認のみ実施）。
  複数問のクイズでの前へ／次への往復は Vitest 側の新規ケースでカバーしている。
- それ以外は計画どおりに実施。
