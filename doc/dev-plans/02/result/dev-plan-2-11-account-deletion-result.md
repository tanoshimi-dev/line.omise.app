# Step 2-11 実装結果 — 自分のアカウント削除（退会）

**対応プラン:** [dev-plan-2-11-account-deletion.md](../dev-plan-2-11-account-deletion.md)

---

## 実施内容

- 認証必須の `DELETE /auth/me` を追加した。リクエストでユーザー ID は受け取らず、認証済みセッションの本人だけを削除する。
- `users` レコードをハードデリートし、外部キー cascade により本人の全セッション、単発クイズ解答履歴、検定受験履歴、および検定配下の解答を削除する。
- API 成功時はセッション Cookie も期限切れにする。これにより、削除を実行した端末だけでなく他端末の既存セッションも無効になる。
- マイページに独立した「退会」セクションを追加した。削除対象と不可逆性を明示し、確認語句 `退会する` の完全一致を要求する二段階確認にした。
- 退会 API 成功後は認証状態を破棄してトップページへ完全遷移する。失敗時はエラーを表示して再試行できる。
- 新しい auth 操作に合わせ、既存のフロントエンドテストの auth mock を更新した。

## テスト

- `go test ./... -v`（`sys/02_backend`）: 成功
  - 未認証時の 401、認証済み退会の 204、Cookie 無効化、全セッション削除を確認。
  - 単発解答・検定受験・検定配下解答が残らず削除され、別ユーザーのデータは残ることを実 DB で確認。
- `npm test`（`sys/03_frontend/web`）: 7 ファイル・31 件すべて成功
- `npm run build`（`sys/03_frontend/web`）: 成功

## 備考

LINE / Google のプロバイダー側アカウント・OAuth 連携許可は削除対象外。退会後に同じプロバイダーで再ログインすると、新しい空のローカルアカウントが作成される。
